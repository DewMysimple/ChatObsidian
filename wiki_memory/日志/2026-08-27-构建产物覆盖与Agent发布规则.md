# 构建产物覆盖与 Agent 发布规则

## 目标

落实“代码或配置迭代直接覆盖旧版本”的约定，使 release exe、固定 NSIS 安装包和已有安装版使用同一发布链路。

## 已确认决策

- 当前迭代版本从 0.1.8 递增为 0.1.9，`package.json`、`src-tauri/Cargo.toml`、`src-tauri/Cargo.lock` 和 `src-tauri/tauri.conf.json` 保持一致。
- `src-tauri/target/release/chat-obsidian.exe` 是固定 release 输出，带版本号的 NSIS 包保留，同时覆盖 `ChatObsidian-latest-setup.exe`。
- 构建和安装只结束 `chat-obsidian.exe`；不调用或结束 `Obsidian.exe`。
- 已安装实例自动静默覆盖升级；应用数据、仓库目录、SQLite、日志、备份和运行时数据保留。
- 进程无法结束、文件被占用、测试失败或安装失败时中止，不跳过文件也不安排延迟替换。
- 仅代码/配置变化触发发布构建；文档、排查和记忆维护不重复打包。完成实质任务后仍提交并推送 `origin/main`，禁止强制推送。

## 实现范围

- 根目录 `AGENTS.md` 增加强制发布覆盖规则。
- `build-installer.ps1` 增加版本一致性检查、ChatObsidian 进程关闭/确认、完整验证、Tauri 构建、固定安装包复制和已有安装检测。
- 构建脚本使用实际 `pnpm.cmd` 并置于 PATH 前端，避免 Tauri 的 `beforeBuildCommand` 误用旧版 Corepack pnpm。
- 构建脚本本身使用 UTF-8 BOM，JSON 读取显式使用 UTF-8，兼容 Windows PowerShell 5.1。
- `src-tauri/windows/hooks.nsh` 通过 `NSIS_HOOK_PREINSTALL` 结束 ChatObsidian 并轮询确认，失败时中止安装；`tauri.conf.json` 注册该钩子。
- `README.md`、发布运维知识页和项目概览同步记录固定产物与数据保留规则。

## 验证结果

- Windows PowerShell 5.1 解析 `build-installer.ps1`：通过；脚本前三个字节为 UTF-8 BOM `EF BB BF`。
- `corepack pnpm typecheck`：通过。
- `corepack pnpm test`：6 个测试文件、18 个测试通过。
- `corepack pnpm test:e2e`：6 个测试通过。
- `cargo test --manifest-path src-tauri/Cargo.toml`：18 个通过、3 个忽略。
- 发布构建：成功生成 0.1.9 release exe 和 NSIS 包；固定 latest 包与版本包 SHA-256 一致。
- 未检测到已有安装，自动升级步骤按设计跳过。
- 9 个外部 Python 脚本未修改，Obsidian 仓库未修改。

## 遗留事项

- 当前机器未安装 ChatObsidian，因此本次只能验证“未安装时跳过自动安装”；安装版覆盖升级需在存在旧安装的 Windows 环境复验。
- 构建产物位于 Git 忽略目录，不提交二进制文件。
