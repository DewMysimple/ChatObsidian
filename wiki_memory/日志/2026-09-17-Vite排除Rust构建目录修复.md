# Vite 排除 Rust 构建目录修复

## 发现与修复

在 [[日志/2026-09-17-Notion风格本地数据库工作台重做]] 的发布收尾中，读取开发服务器退出信息时发现：Vite 监听到了 `src-tauri/target/release/deps/` 中正在链接的 exe，触发 Windows `EBUSY` 并退出。这不影响已成功生成的 0.1.14 发布包，但会干扰同时运行的桌面开发流程。

在 `vite.config.ts` 的 `server.watch.ignored` 中排除 `**/src-tauri/**`，Rust 文件继续由 Tauri 自身管理。按版本规则递增到 0.1.15，同步版本文件、Cargo 锁文件、界面、README 和演示截图。

## 验证与发布

- 读取实际 Vite watcher 的监听路径，确认不含 Rust 目录。
- 保持 Vite 运行并完整执行 `build-installer.ps1`，最终 Rust 链接和 NSIS 打包后 HTTP 请求仍返回 200；随后正常关闭本次验证服务器。
- 类型检查、15 项前端测试、11 项 Playwright 流程、18 项 Rust 常规测试、格式检查均通过。数据与窗口逻辑未在本次补丁中改动，前次临时旧库迁移验证仍适用。
- 首次并行验证辅助进程继承了不合适的 PowerShell 模块路径，在 Get-FileHash 步骤失败，安装未执行。修正辅助进程使用的 PowerShell，并清除该验证程序引入的 NODE_ENV 后重新完整运行成功；最终前端使用生产构建，JS 主包约 361 KB。
- 0.1.15 exe、版本安装包与 latest 均成功生成且安装包哈希一致，0.1.14 版本安装包保留。未检测到已有安装，自动安装按规则跳过，没有启动应用或结束 Obsidian。
- 追加本日志、更新索引、运行记忆 lint，并创建修复提交与普通推送。
