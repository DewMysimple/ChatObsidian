# 工程架构审查

## 目标

回答当前 ChatObsidian 的工程架构，并用实际代码入口、模块和配置核对长期记忆中的架构结论。

## 确认的架构

- 应用是 Windows 11 x64 单机桌面应用，采用 Tauri 2；React/TypeScript/Vite/Zustand 负责界面，Rust 负责本地文件、SQLite、Obsidian 窗口、同步、脚本和 Windows 桌面能力。
- 前端通过 `src/lib/desktop.ts` 的稳定桥接调用 Tauri command；浏览器演示模式使用 mock，不访问本地文件。
- Rust 通过 `AppState` 共享 SQLite 连接、偏好和应用路径；扫描、索引、差异、同步和配置检查等高耗时 I/O 经 `spawn_blocking` 执行。
- 主窗口与快速切换器是两个 Tauri WebView 窗口；单实例、托盘、开机自启、全局快捷键和跨虚拟桌面打开逻辑位于 Rust 桌面层。
- SQLite 使用 WAL，保存仓库目录、分组、笔记标题索引、操作记录、配置快照和配置哈希缓存；笔记正文不进入索引。
- 同步采用“模板 + 仓库例外”，执行前计算差异和备份，按目标顺序写入并保留回滚记录；工具箱只允许固定脚本并执行预检。
