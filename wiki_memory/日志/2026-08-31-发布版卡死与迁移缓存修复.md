# 发布版卡死与迁移缓存修复

## 现象与根因

- 新路径下 exe 文件存在，但同时出现 3 个 ChatObsidian 进程，均不响应。
- 最早的后台实例运行期间，主窗口每 4 秒发起一次配置变化检查；请求未完成时没有并发保护，后台线程持续累积到 500+，最终拖垮 WebView2。
- 项目跨盘迁移后，旧 `node_modules` 的 pnpm 虚拟商店路径仍指向桌面目录；Cargo 增量缓存也引用旧目录，导致构建读取不存在的旧路径。

## 修复

- `src/App.tsx` 增加配置检查单飞、隐藏暂停、可见恢复立即检查和错误收敛。
- `AppState` 与 `check_active_config_change` 增加 Rust 原子重入保护，前后端双重防止请求堆积。
- 版本递增至 0.1.12，重新建立 pnpm 链接并清理 `src-tauri/target` 旧路径构建缓存。

## 验证

- 清理卡死实例后，单次启动新 release exe 在 8 秒后 `Responding=True`，仅 1 个 ChatObsidian 进程，线程数稳定为 42。
- `corepack pnpm typecheck` 通过。
- `corepack pnpm test`：6 个测试文件、20 个测试通过。
- `corepack pnpm test:e2e`：6 个流程通过。
- `cargo test --manifest-path src-tauri/Cargo.toml --lib`：19 通过、3 忽略、0 失败。
- `build-installer.ps1` 成功生成并覆盖 release exe、版本安装包和 `ChatObsidian-latest-setup.exe`；两个安装包 SHA-256 一致。

## 结果与遗留

- 新发布版已写入 `src-tauri/target/release/chat-obsidian.exe`，启动验证正常；构建脚本未自动重新启动应用以避免重复实例。
- 当前未检测到注册表安装版，因此没有执行静默安装升级；便携 release exe 可直接运行。
- 迁移时保留的旧依赖目录已改名为 `node_modules.stale-after-relocation`，仅用于回收前的安全保留，不参与构建。
