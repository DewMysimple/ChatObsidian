# 构建与正式产物目录隔离和历史清理

## 目标与已确认要求

用户要求工程只保留最新版本的过程产物、正式应用和应用压缩包，删除按版本堆积的旧构建目录；正式应用应放在 dist，开发构建不能覆盖日常使用的程序。每次完成修改后应构建压缩包，并实际解压成完整正式应用。

本次目录与保留规则取代 [[日志/2026-08-27-构建产物覆盖与Agent发布规则]]、[[日志/2026-09-17-Vite排除Rust构建目录修复]] 中保留版本安装包和从 Rust target 直接运行的安排；历史日志不改写。

## 检查与实现

- 清理前，原 src-tauri/target、target-v0.1.1、target-v0.1.2、target-validation 和 node_modules.stale-after-relocation 的文件总大小为 19,029,302,197 字节，约 17.72 GiB。此为逻辑文件大小汇总，不等同于精确物理扇区释放量。
- Vite 输出迁至 .build/frontend，Tauri frontendDist 同步修改，预览沿用同一目录。监听排除 Rust、.build 和 dist，防止链接器占用和发布清理触发开发服务器异常。
- 根目录 .cargo/config.toml 将 Cargo 输出固定为 .build/cargo，关闭额外增量缓存。根目录和 src-tauri 内执行 cargo metadata 都验证输出指向同一目录。Playwright 最近结果移至 .build/test-results。
- build-installer.ps1 运行记忆 lint、版本检查、发布脚本测试、前端测试、浏览器流程和 Rust 测试，完成原生编译和 NSIS 打包后才进入正式更新阶段。
- scripts/release.ps1 把 exe 和运行说明压缩到 ZIP，再从这个 ZIP 实际解压；检查解压文件、ZIP 内容、构建源 exe 和安装包 SHA-256。dist/release.json 保存版本、时间和逐文件校验值。新增外部 Tauri 资源时会要求先扩展打包规则，避免遗漏运行文件。
- 正式目录使用固定名称：dist/ChatObsidian、dist/ChatObsidian-windows-x64.zip、dist/ChatObsidian-latest-setup.exe。测试/编译/压缩期间保留旧正式目录；最终替换通过临时旧目录支持失败恢复和中断后的恢复。成功后删除临时旧版。
- pnpm tauri:dev 与发布脚本共用文件句柄锁，持锁进程退出后锁自然释放。发布前清理固定 Cargo 目录，成功后清理本次 Cargo 目录、旧 target 目录和迁移残留依赖，避免旧依赖哈希及 PDB 继续堆积。
- 清理与移动先验证绝对路径属于工程允许的输出目录，拒绝外部路径、源码目录、根目录、符号链接/目录联接和未知 dist 文件。当前依赖、全局工具链缓存、源代码、应用数据库、SQLite 快照、用户仓库不参与清理。
- 已移除根目录旧验证日志和旧 test-results；当前测试输出保留在 .build。README、根 AGENTS 与开发入口均更新。版本递增为 0.1.16，三个版本文件、Cargo 锁文件与界面版本保持一致。

## 验证与结果

- 24 项发布流程检查通过：包括旧 Vite 输出识别、候选不提前发布、ZIP/解压一致性、损坏文件拒绝、替换失败恢复、中断恢复、并发锁、越界/源码路径拒绝、嵌套联接拒绝、历史目录精确匹配和未知文件保留。
- 类型检查、15 项 Vitest、11 项 Playwright、18 项 Rust 常规测试通过；两项真实环境测试仍按原配置忽略。Prettier、cargo fmt 和 git diff 检查通过。
- 初次完整发布在最终更新前发现旧进程检查函数对空结果使用 Count，在严格模式下报错；dist 与旧构建目录均保留。改为显式数组后，以模拟空进程列表验证，并重新执行完整发布成功。
- 第二次发布期间检测到正在使用旧 target/release 路径的 ChatObsidian。只在全部构建、压缩和解压验证通过后请求关闭它；仍驻留后按既有发布规则结束该应用进程。未结束 Obsidian，未检测到安装版，因此跳过自动安装，未自动重启应用。
- 最终 exe 文件版本为 0.1.16。正式目录含 exe、运行说明、ZIP、NSIS 和清单共 5 个文件，总大小约 19.98 MiB；逐文件与 ZIP 条目校验全部通过。
- 在正式 exe 持有禁止写入/删除的文件句柄时再次运行 pnpm build，成功且所有 dist 校验值保持不变，证明前端构建不会清空或覆盖正式应用。
- 实地检查确认旧 target、两个 target-v 目录、target-validation、残留依赖、.build/cargo、发布暂存和临时旧版均不存在；.build 仅保留最新前端、最近测试结果和锁文件。
- 完成记忆索引、lint、Git 提交和普通推送；不提交二进制产物。

## 使用与限制

日常从 dist/ChatObsidian/chat-obsidian.exe 启动。完整发布使用 build-installer.ps1 或 pnpm release；低层 tauri:build 仅用于打包排查。发布清理 Cargo 缓存后，下次 Rust 编译会冷构建，明确以时间换磁盘空间。

解压版包含本应用完整文件，使用系统 WebView2；不是独立数据配置的绿色版，仍使用原用户应用数据路径。Windows 正式更新运行中的 exe 需要短暂退出，开发构建与打包阶段不会主动关闭日常应用。桌面开发仍使用当前用户数据，不能用其执行破坏性测试。失败时固定的本次构建/候选目录可供排查，下次发布覆盖；成功状态不积累历史版本。

实现依据参考 Cargo 官方构建缓存/配置文档和 Tauri 官方 Windows 分发文档，相关链接已写入 README。

## 待确认长期记忆

- .build 为唯一过程输出根目录，dist 为最新完整正式应用、ZIP、安装包和校验清单；用户授权的只保留最新版本规则优先于旧 active 记忆中的版本安装包保留规则。
- 默认以冷构建时间换磁盘容量，成功发布后清空 Rust 编译缓存；日常入口不能指向 Cargo target。
- 发布应先压缩再解压验证，最后才替换正式目录；保留期间失败恢复能力，但成功后不保留历史版本。

候选未提升为 active 页面；本次用户已要求的目录规则已落实到根 AGENTS 和实际脚本。
