# 系统架构

## 分层

1. React 页面层负责仓库中心、同步中心、模板、工具箱、历史和偏好设置。
2. Zustand 保存当前页面、仓库、分组、操作、偏好和 Toast 状态。
3. src/lib/desktop.ts 是稳定的前端桌面桥接；Tauri 环境调用 Rust command，浏览器环境返回 mock。
4. Rust command 层负责线程调度、参数校验和权限边界。
5. Rust 领域模块分别处理仓库发现、Obsidian 窗口、同步、脚本、设置、SQLite 和 Windows 桌面。

## 数据流

- 启动时读取 %APPDATA%\ChatObsidian\settings.json 和 SQLite。
- 首次为空目录时执行完整仓库扫描；已有目录时优先快速刷新 Obsidian 注册表元数据，避免启动阻塞。
- 笔记索引只保存标题、相对路径、仓库和修改时间，不保存正文。
- 快速切换浮窗通过 `refresh_quick_switcher` 刷新注册表元数据和真实 Obsidian 窗口状态；可见期间低频重建笔记标题索引，隐藏后停止轮询。
- 高耗时操作通过 spawn_blocking 执行，包括扫描、差异、同步、回滚和配置检查。
- 前端不拥有任意文件写入或任意命令执行权限；危险能力集中在 Rust 后端。

## SQLite 表

当前数据库包含仓库、分组、笔记索引、操作记录、配置快照和哈希缓存相关表。仓库主键使用 ChatObsidian 稳定 ID，并同时保存 Obsidian Vault ID（如果可用）。

## Windows 打开链路

调用方窗口先确定当前桌面。目标仓库已在当前桌面时直接聚焦；只在其他桌面时按策略正常关闭，再通过普通 Obsidian Vault URI 重开。不会使用 paneType=window，也不移动外部 Obsidian 窗口。
